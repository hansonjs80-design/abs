# C-Arm 통계

- 물리치료 통계 오른쪽의 독립 탭입니다. 제목은 선택 연월에 맞춰 `2026년 09월 장곡 씨암 현황`처럼 표시합니다.
- `방사선사 설정`에서 이름과 인원을 변경합니다(최대 30명). 건수가 있는 사람은 제거할 수 없습니다. 이름 변경은 같은 사람의 기록에 유지됩니다.
- 초진/재진 일별 건수를 직접 입력하면 개인 합계, 전체 합계, 월별/연간 건수와 인센티브가 즉시 계산됩니다.
- 엑셀/구글 시트의 여러 행·열을 시작 건수 칸에 붙여넣을 수 있습니다. 초진·재진 다음 열은 다음 방사선사로 이어집니다. 날짜 열이 포함되면 선택한 시작 날짜와 일치하는지 확인하며, 숫자 오류나 월/열 범위 초과 시 전체 붙여넣기를 취소합니다. 빈 셀은 기존 값을 비웁니다.
- 공휴일 설정에 등록된 날짜는 일요일과 함께 빨간색으로 표시합니다. 날짜와 괄호 요일은 같은 크기로 가운데 정렬합니다.
- 입력 후 0.7초간 추가 변경이 없으면 자동 저장하며, 월/탭 이동 시 대기 변경도 저장합니다. 저장 실패 시 입력을 보존하고 다시 저장 버튼을 표시합니다. 브라우저를 닫기 전 자동 저장 완료 상태를 확인해주세요.
- 클릭 또는 드래그로 셀 범위를 선택합니다. Ctrl/Cmd+C/X/V로 복사·잘라내기·붙여넣기, Delete로 선택 영역 지우기, Ctrl/Cmd+Z 및 Shift+Z로 실행 취소/다시 실행을 지원합니다. 방향키와 Tab/Enter로 이동하고 Shift+방향키로 선택 영역을 늘릴 수 있습니다.
- 건당 단가(기본 2,000원)와 방사선사 구성은 월별로 보관합니다. 새 달은 가장 최근 이전 월의 저장된 구성을 이어받으며 건수는 복사하지 않습니다. 과거 단가나 이름은 자동 변경하지 않습니다.
- `c_arm_monthly_stats` 전용 테이블만 사용합니다. 충격파/신장분사/도수/물리치료 기록, 통계, 인센티브에 합산하지 않습니다.
- 동시에 같은 달을 편집하면 revision 비교로 나중 요청의 덮어쓰기를 막습니다. 충돌/연결 실패 시 입력은 보존되며, 확인 후 서버 기록을 다시 불러올 수 있습니다.
- 일반 계정은 `c_arm_stats: true`를 명시적으로 부여해야 메뉴와 URL 접근이 허용됩니다. 관리자에게는 항상 허용됩니다. 설정 > 로그인 관리에서 C-Arm 통계를 체크하고 저장합니다.
- 기존 앱은 `app_users` 기반 로그인으로 Supabase Auth 세션을 발급하지 않습니다. 따라서 이 탭도 기존 앱의 메뉴/경로 접근 제어를 따릅니다. DB 자체의 계정별 RLS를 제공하는 구조는 아닙니다.

## DB 적용 및 백업

운영에 `supabase/migrations/20260929_c_arm_monthly_stats.sql`을 적용했습니다. 이 SQL은 기존 치료 테이블을 변경하지 않습니다. 전체 `supabase_schema.sql`에는 신규 설치용 정의도 포함했습니다. 기존 프로젝트에는 위 개별 마이그레이션만 사용합니다.

2026-09-29 00:28:37 UTC에 운영 public 12개 테이블 데이터와 컬럼/제약/인덱스/정책/함수/트리거/권한 메타데이터를 일관된 repeatable-read 스냅샷으로 백업했습니다. `backups/c-arm-before-<project>-2026-09-29T00-28-37-209Z.json`에 소유자 전용(0600)으로 저장하고 파일 재읽기, 프로젝트, 시각, 12개 테이블 및 행 수를 검증했습니다. Auth/Storage는 변경 대상이 아닙니다.

행 수: app_users 6, holidays 40, manual_therapy_patient_logs 346, manual_therapy_therapists 2, notices 15, shockwave_monthly_therapists 22, shockwave_patient_logs 1311, shockwave_schedules 6610, shockwave_settings 2, shockwave_therapists 9, staff_calendar_settings 2, staff_schedules 1114. 적용 직후 기존 행 수 동일, 신규 테이블 0행을 확인했습니다.

복구 시 기존 테이블에는 복원 쓰기를 하지 않습니다(이 마이그레이션은 기존 데이터를 수정하지 않음). 신규 테이블을 되돌려야 한다면 먼저 새 C-Arm 기록까지 추가 백업하고 테이블 제거의 영향을 검토해야 합니다. 일반 앱 백업/복원 목록에는 새 테이블을 포함했습니다. 위 운영 전 스냅샷은 메타데이터를 포함한 별도 검증 형식이므로 앱의 JSON 복구 스크립트에 직접 전달하지 않습니다.
