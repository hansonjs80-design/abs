# PT현황 총치료 건수 표시

`StaffCalendar`는 `usePTCalendarCounts` 훅으로 같은 Supabase의 PT 날짜별 `total_count`와 공용 적용 범위를 읽습니다. 환자 상세 행은 읽지 않습니다. 최초 범위는 PT현황을 연결한 날부터이며 PT현황 설정 → 근무표 PT건수에서 모든 날짜 또는 지정일부터로 변경할 수 있습니다.

각 주의 설정된 마지막 메모칸에 `47명`처럼 표시합니다. 값은 PT현황 총치료 건수이며 중복 환자의 여러 치료 행도 각각 포함합니다. 기존 `staff_schedules` 메모 및 서식은 수정하지 않습니다. 연동 범위 밖 또는 PT 데이터가 없는 날짜는 기존 메모를 유지하며, 연동된 건수의 툴팁에서 원래 메모도 확인할 수 있습니다. 마지막 행 숨기기 설정은 그대로 적용됩니다.

공용 범위는 `pt_daily_records.date = __pt_staff_calendar_count_settings_v1__`의 `rows_data[0].staffCalendarCounts`에 저장됩니다. `scope`는 `today`, `all`, `from`이고, `today`와 `from`의 `startDate`는 ISO 날짜입니다. `today`도 저장 시점의 날짜로 고정되어 이전 건수가 다음 날 사라지지 않습니다. 근무자동화는 이 레코드를 포함해 DB에 쓰지 않습니다. 달력 이동 시 해당 달력에 보이는 인접 날짜도 함께 조회합니다.

PT 앱의 `pt-live-updates-v1` 방송 및 DB 변경 이벤트를 구독하며 보이는 동안 10초 간격 확인, 온라인 복귀 및 화면 복귀 재조회로 보완합니다. 조회는 12초 후 중단하고, 일시적 실패에는 마지막 확인된 건수를 유지하며 툴팁에 지연 상태를 표시합니다. 월 이동 후 이전 월의 결과는 적용하지 않습니다.

2026-10-10 사전 백업은 이 폴더와 PT현황 폴더의 Git 제외 `supabase-backups/pt-staff-2026-10-10T03-23-48.016444+00-00/`에 있습니다. 직접 DB 읽기 전용 스냅샷으로 PT 기록·설정 213개, 근무표 메모 1,130개, 달력 설정 2개를 백업하고 행 수와 SHA-256을 검증했습니다. 변경은 기존 테이블의 공용 설정 레코드 하나 추가만 필요하며 스키마·정책·Auth·Storage 변경은 없습니다.
