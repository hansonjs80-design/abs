# PT현황 총치료 건수 표시

`StaffCalendar`는 `usePTCalendarCounts` 훅으로 같은 Supabase의 PT 날짜별 `total_count`와 공용 적용 범위를 읽습니다. 환자 상세 행은 읽지 않습니다. 최초 범위는 PT현황을 연결한 날부터이며 PT현황 설정 → 근무표 PT건수에서 모든 날짜 또는 지정일부터로 변경할 수 있습니다.

PT현황 설정의 **PT건수 연동 사용**을 해제하고 저장하면 공용 설정의 `enabled`가 `false`로 저장됩니다. 근무표는 기존 하단 메모·건수를 표시하고 날짜별 PT건수 조회도 중단합니다. 설정 레코드 확인은 계속해 다시 켠 상태를 자동 반영합니다. 적용 범위·시작일과 원본 기록은 보존되며, 기존 설정처럼 `enabled` 필드가 없으면 활성화 상태로 처리합니다.

## 수동 수정

마지막 메모칸을 더블클릭하거나 Enter/F2로 편집해 수동 건수를 입력할 수 있습니다. 편집 시작 시 현재 표시된 건수를 불러옵니다. 수동 내용은 기존 `staff_schedules.content`에 저장하고, 편집 시점의 PT 총치료 건수는 `pt_daily_records`의 `__pt_staff_manual_count_v1__YYYY-MM-DD` 레코드에 보관합니다. 두 기기와 새로고침에서도 수동값을 유지합니다. 일반 메모·서식 저장 로직은 그대로 사용하며 실제 환자 날짜 레코드에는 쓰지 않습니다.

PT 총치료 건수가 유지되는 동안 수동값을 표시하고, 해당 날짜의 건수가 바뀌면 PT 건수로 다시 표시합니다. 이름·메모만 수정해 총치료 건수가 같으면 수동값을 유지합니다. 변경을 확인한 수동 기준은 비활성화해 건수가 나중에 원래 값으로 돌아와도 과거 수동값이 다시 나타나지 않습니다. 다른 기기의 새 수정은 revision 비교로 보호합니다. 자동 갱신은 기존 근무표 원문을 덮어쓰지 않으므로 연동을 끄면 마지막 수동 입력도 확인할 수 있습니다.

각 주의 설정된 마지막 메모칸에 `47명`처럼 표시합니다. 값은 PT현황 총치료 건수이며 중복 환자의 여러 치료 행도 각각 포함합니다. 자동 연동은 기존 `staff_schedules` 메모 및 서식을 수정하지 않습니다. 사용자가 직접 편집한 값은 기존 메모 저장 방식으로 저장합니다. 연동 범위 밖 또는 PT 데이터가 없는 날짜는 기존 메모를 유지하며, 연동된 건수의 툴팁에서 원래 메모도 확인할 수 있습니다. 마지막 행 숨기기 설정은 그대로 적용됩니다.

공용 범위는 `pt_daily_records.date = __pt_staff_calendar_count_settings_v1__`의 `rows_data[0].staffCalendarCounts`에 저장됩니다. `scope`는 `today`, `all`, `from`이고, `today`와 `from`의 `startDate`는 ISO 날짜입니다. `today`도 저장 시점의 날짜로 고정되어 이전 건수가 다음 날 사라지지 않습니다. 근무자동화는 이 공용 설정과 실제 PT 날짜 레코드를 수정하지 않습니다. 수동 입력 기준만 별도의 예약 레코드에 저장합니다. 달력 이동 시 해당 달력에 보이는 인접 날짜도 함께 조회합니다.

PT 앱의 `pt-live-updates-v1` 방송 및 DB 변경 이벤트를 구독하며 보이는 동안 10초 간격 확인, 온라인 복귀 및 화면 복귀 재조회로 보완합니다. 조회는 12초 후 중단하고, 일시적 실패에는 마지막 확인된 건수를 유지하며 툴팁에 지연 상태를 표시합니다. 월 이동 후 이전 월의 결과는 적용하지 않습니다.
